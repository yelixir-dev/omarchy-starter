00 · Required — Before you install

Before you install, check these.

Go through this list before you boot the Omarchy USB stick. Most of the problems people hit during installation can be avoided here. For the installation itself, follow the official manual.

  1. Turn off Secure Boot and TPM in the BIOS

    Omarchy can't be installed while they're on. The official manual says to turn them off before you start.

  2. Back up your important files first

    Copy photos, documents, and anything else you can't lose to an external drive or the cloud. Installing wipes or repartitions disks, and one wrong choice can't be undone.

  3. Choose a full-disk or a free-space install

    A full-disk install erases the chosen disk and leaves only Omarchy. To keep Windows alongside it (dual boot), shrink a Windows volume to make free space, then pick Free space install in the installer. Turn off BitLocker (device encryption) in Windows first. When the install is done, run limine-scan to add Windows to the boot menu.

  4. You type the disk password before the desktop loads

    Omarchy encrypts the disk by default, so it asks for a password every time it boots, before the desktop appears. Bluetooth keyboards don't work on that screen, so use a wired keyboard or one with a 2.4GHz dongle. Pick the English (US) layout during installation; Korean input is set up separately in chapter 02.

  5. The disk password and your user password are different

    The disk password unlocks the machine at boot; your user password is for logging in and for sudo. Even if you used the same value during installation, changing your user password later (passwd) leaves the disk password as it was, so remember both.

  6. Have wired internet or USB tethering ready

    Laptops with Broadcom Wi-Fi and older Macs may not see Wi-Fi right after installation. An Ethernet cable or USB tethering from your phone gets you online in the meantime, so you can finish installing and updating.

  7. Black installer screen on NVIDIA? Try nomodeset

    Adding nomodeset to the boot options in the USB stick's boot menu can bring the installer up. It's only a workaround to get the installer on screen, so don't keep it in the installed system.

  8. Snapshots only restore the system

    Omarchy takes a system snapshot before updates so you can roll back if something breaks. Snapshots don't restore your personal files in /home, so keep a real backup.

  9. Keep the official manual handy

    The installation is covered, with pictures, in Getting started and Dual boot install. learn.omacom.io, which still shows up in searches, is the old v3 manual.

Fast path — Install everything at once

Install everything at once.

This installer lets you pick your post-install setup on one screen and run it with a single Enter. Items you already have start at [-], and missing required and recommended items start at [v], so on a fresh system you can simply run it. Every chapter below still has the copy-paste commands for doing the same thing by hand.

Run it

curl -fsSL https://raw.githubusercontent.com/yelixir-dev/omarchy-starter/main/install.sh | bash

git clone https://github.com/yelixir-dev/omarchy-starter.git && cd omarchy-starter && ./install.sh

01 · Recommended — OMO coding agent

Install the OMO coding agent.

A coding agent is an AI tool you talk to in the terminal. Ask it something like "install the Korean input method" and it writes and runs the commands for you. If Linux is new to you, you can hand every step of this guide to an agent; that's what the "Ask an AI" prompts are for. The one thing an agent can't do is install itself, so follow this chapter's commands by hand. Once it's installed, you can ask OMO to do the later chapters.

OMO is one such agent. It's recommended but not required; if you already use another AI tool, keep using it.

Install it yourself

Install with bun and sign in

First, open a terminal by pressing Super + Enter. On a Mac keyboard, the Command key is Super.

Run these commands one line at a time.

omarchy install dev-env bun
echo 'export PATH="$HOME/.bun/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
bun i -g omo-ai
omo
  1. Install bun. Omarchy doesn't ship bun, so the first line installs it. Node.js is already installed through mise; check with node -v.
  2. Add it to PATH. bun puts global commands in ~/.bun/bin, which isn't on Omarchy's PATH. The echo line adds it, and source applies it to the current terminal.
  3. Install OMO. A "Blocked 3 postinstalls" message during bun i -g omo-ai is normal.

When OMO opens, type this in the input box and follow the prompts to sign in.

/login

After that, run omo in whatever folder you want to work in.

No bun? npm works too

If installing bun fails, the npm that's already there works: run npm i -g omo-ai. Since omo 5.0.0 the stable release is on the default tag, so the old @beta suffix is no longer needed. If you installed omo-ai@beta with npm earlier, remove it with npm rm -g omo-ai and install again.

Already have an AI agent? Ask it like this

OMO can't install itself before it exists, so follow the Install it yourself steps above. If you already have Claude Code, ChatGPT, or another AI tool, paste this in: 

My computer runs Omarchy (Arch Linux). Please install the OMO coding agent.
Install bun with omarchy install dev-env bun, add ~/.bun/bin to the PATH in
~/.bashrc, then install it with bun i -g omo-ai. When it's done, walk me through
running omo and signing in with /login step by step. I'm a beginner.
Give me one command at a time and explain what each one does.

02 · Required — Korean input

Set up Korean input.

Typing Korean on Linux takes an input method. Omarchy 4 already ships Fcitx5, the input method framework, along with its GTK and Qt modules, the environment variables, a user service that keeps it running (omarchy-fcitx5), and Noto CJK fonts to display Hangul. What's missing is the Hangul engine (fcitx5-hangul) and the configuration tool (fcitx5-configtool). Once the engine is in, Ctrl + Space switches between Korean and English. If you type Korean, don't skip this chapter.

Before you start

Check that this guide fits your system

The script targets Arch-based systems. It uses Omarchy's package command when Omarchy is present and pacman on other Arch systems.

  • You need to be able to type your password in a terminal.
  • Run it inside a Wayland or X11 graphical session.
  • If you already have an Fcitx5 profile, the script backs it up with a timestamp first.
Install it yourself · Step 1

Get the script

Clone this guide's repository and use the install-fcitx5-hangul.sh inside it as it is. 

git clone https://github.com/yelixir-dev/omarchy-starter.git
cd omarchy-starter
chmod +x install-fcitx5-hangul.sh

If you downloaded just the script with the link above, it's usually in your Downloads folder. 

cd ~/Downloads
chmod +x install-fcitx5-hangul.sh
Install it yourself · Step 2

Run the installer script

If it asks for a password, enter your user password. Packages that are already installed aren't reinstalled. 

./install-fcitx5-hangul.sh

The script does the following, in order:

  1. Leaves fcitx5 and the GTK/Qt modules Omarchy already has alone, and installs the missing Hangul engine and configuration tool.
  2. Backs up your current profile as profile.bak.date-time.random, so nothing gets overwritten.
  3. Restarts Omarchy's input method service if Fcitx5 isn't running.
  4. Adds the US keyboard and the Hangul input method to the default group and saves it.
  5. On X11, writes the input method environment variables to a separate file.
  6. Checks that hangul shows up in the result.
Install it yourself · Step 3

Switch to Korean

On a fresh setup, press Fcitx5's default toggle, Ctrl + Space. If you changed the toggle key before, you can check it under Global Options in fcitx5-configtool. 

Typed on the English layout: gksrmf
Composed Korean result:      한글

Still typing English after switching?

Apps that were already running may not have picked up the new input method yet. Quit the app completely and reopen it; if that doesn't help, log out and back in.

Install it yourself · Step 4

Check the installation

These commands show the packages and the input method group.

pacman -Q fcitx5 fcitx5-hangul libhangul
fcitx5-remote -q
fcitx5-diagnose
  • All three packages print a version.
  • The input method group is usually Default.
  • Under Input Methods in fcitx5-diagnose, you see keyboard-us and hangul.

Ask an AI

Clone https://github.com/yelixir-dev/omarchy-starter and use the
install-fcitx5-hangul.sh script inside it to install Korean input for Fcitx5.
Afterwards, check that keyboard-us and hangul are registered,

Troubleshooting

Where people get stuck

I can't enter my password

Run the script in a terminal, not from a graphical pop-up. Package installation asks for the sudo password in the terminal.

Korean works in some apps but not others

Quit that app completely and start it again. Apps that were open before the installation may need to reload the input method environment.

Korean input suddenly stopped working

Restart Omarchy's input method service.

systemctl --user restart omarchy-fcitx5

Don't start another fcitx5 by hand in a terminal. It fights the one the service already runs over the D-Bus name, and input gets worse.

Restore your previous input method list

In ~/.config/fcitx5/, find the newest profile.bak.* file, copy it back to profile, then restart Fcitx5 with the service command above.

Optional — Korean/English key

Use Right Alt as the Korean/English key

To switch languages with Right Alt (Right Option on a Mac), as on a Korean Windows keyboard, pick Korean/English key in Install everything at once. It also makes the Super + Space menu always open with English input, so searches don't come out in Hangul, and it can take Ctrl + Space off language switching so programs like tmux can use it.

03 · Required — Default editor

Make nano the default editor.

Omarchy's default terminal editor is Neovim. It's powerful, but newcomers get stuck on the very first question: how do I save and quit? So that a git commit message or a config file opened from the menu doesn't trap you, switch the default to nano, which always shows its shortcuts at the bottom of the screen.

Install it yourself

Install nano and make it the default

First, install nano.

omarchy pkg add nano

Then write nano into the file that stores your default editor.

mkdir -p ~/.local/state/omarchy/defaults && echo nano > ~/.local/state/omarchy/defaults/editor

Omarchy's EDITOR is omarchy-launch-editor --inline, which opens whatever editor that file names. So git commit messages and the menu's "edit" actions all open in nano. It takes effect in new terminals.

In nano, Ctrl + O saves and Ctrl + X quits.

To go back to Neovim, delete that file.

rm ~/.local/state/omarchy/defaults/editor

Ask an AI

My computer runs Omarchy (Arch Linux). Please make nano the default terminal editor.
Install it with omarchy pkg add nano, then write the single line nano into
~/.local/state/omarchy/defaults/editor. After that, check that git commit
opens nano in a new terminal.

04 · Optional — Intel Mac trackpad

Palm rejection on 2019-and-older Intel Macs.

Palm rejection keeps the cursor still when your palm brushes the trackpad while you type. On 2019-and-older Intel Macs the built-in trackpad is sometimes reported to the system as "external," which leaves this feature switched off. Whether you need the fix is better judged from the model identifier, such as MacBookAir8,2, and the actual classification than from the release year. If this doesn't apply to you, skip the chapter.

The cause on the test machine

On a 2019 MacBookAir8,2, the built-in trackpad passes through the T2 chip's virtual USB and was misclassified as external. So even with the Hyprland setting on, libinput reported Disable-w-typing: n/a.

Install it yourself · Step 1

Check whether your Mac needs it

If the Apple trackpad entry shows Disable-w-typing: n/a, this script is for you. If it already says enabled, you don't need it. 

omarchy pkg add libinput-tools
libinput list-devices

This prints the model identifier:

cat /sys/class/dmi/id/product_name
Install it yourself · Step 2

Preview the changes first (dry run)

Make install-intel-mac-palm-rejection.sh from the same folder executable, then start with the check that changes nothing. 

git clone https://github.com/yelixir-dev/omarchy-starter.git
cd omarchy-starter
chmod +x install-intel-mac-palm-rejection.sh
./install-intel-mac-palm-rejection.sh --dry-run

The output should list the Apple trackpad, its USB ID, and its current classification.

Install it yourself · Step 3

Fix the built-in trackpad's classification

./install-intel-mac-palm-rejection.sh

The script finds the built-in Apple trackpad's USB ID and adds an internal classification to the udev hwdb. It doesn't install old kernel patches or extra input daemons.

You need to log out

The configuration is installed right away, but the running Hyprland keeps using the old device object. Log out and back in, or reboot, after applying it.

Install it yourself · Step 4

Confirm enabled, or roll back

After logging back in, run the command below. If the Apple trackpad entry now shows Disable-w-typing: enabled, the fix is working. 

libinput list-devices

If something goes wrong, the installer can remove just its configuration.

./install-intel-mac-palm-rejection.sh --uninstall

  • Omarchy T2 root-cause notes

05 · Optional — VPN

Install VPNs and use them together.

"VPN" means two different things here. One is a VPN that connects your own devices (Tailscale); the other is a VPN that changes where your internet traffic exits (NordVPN). Same name, completely different jobs, and set up correctly they run at the same time. This chapter installs each one, then shows how to use both without conflicts.

Don't use the Omarchy menu's VPN installers

For this setup, don't use Install › Service › Tailscale or NordVPN from the Omarchy menu. Omarchy's Tailscale installer runs tailscale up --accept-routes and adds its own bar panel, so you may end up with two Tailscale icons next to this guide's toggle. Its NordVPN installer installs the native NordVPN app (the nordvpn command), which this guide avoids.

05-1 · Tailscale

Install Tailscale

Tailscale joins your PC, laptop, and phone into one private network. Once you sign up, each device gets a fixed 100.x.x.x address, and you can reach the PC at home or a server abroad at that address, even from café Wi-Fi. The author uses it to reach a file server on an old laptop (a ThinkPad T420) in another room.

Why install it? It's the easiest way to reach your other devices remotely, share files between them, or let an AI agent manage your other computers.

Install it yourself

Install and connect to your account

Run these one line at a time.

omarchy pkg add tailscale
sudo systemctl enable --now tailscaled
sudo tailscale up --accept-routes=false

The last command opens a sign-in page in your browser. Sign in with Google or another account and this computer joins your network. --accept-routes=false is a safety option: it refuses routes advertised by other devices.

Check the connection:

tailscale status
tailscale ping <other-device-name>

Ask an AI

My computer runs Omarchy (Arch Linux). Please install Tailscale.
Install it with omarchy pkg add tailscale, enable the tailscaled service at
boot, then run tailscale up so I can sign in through the browser.
Always keep the --accept-routes=false option.
Once I'm signed in, check with tailscale status that my other devices show up.

05-2 · NordVPN

Install NordVPN

NordVPN sends all of your internet traffic through a server in another country, so your public IP address becomes one from that country. People use it for region-locked services or to protect traffic on public Wi-Fi.

This guide doesn't use NordVPN's native app (the nordvpn command). It sets NordVPN up as an OpenVPN profile in NetworkManager, Linux's standard networking tool, because the native app can conflict with Tailscale (explained in the next section).

Install it yourself · Step 1

Add OpenVPN support and import a config

omarchy pkg add networkmanager-openvpn

Download the .ovpn file for the country you want from NordVPN's official server list and import it into NetworkManager. 

nmcli connection import type openvpn file /path/to/jp878.nordvpn.com.udp.ovpn

Turn off autoconnect for the imported profile, and block regular IPv6 while the VPN is up.

nmcli connection modify nordvpn-omo-split connection.autoconnect no
nmcli connection modify nordvpn-omo-split +ipv6.routes "::/0 type=blackhole"

The profile name depends on what the import created.

Install it yourself · Step 2

Save the service credentials

Since June 2023, your NordVPN account email and password no longer work for OpenVPN. Use the Username and Password from Set up NordVPN manually → Service credentials in your Nord Account.

This command stores the password in the profile without showing it on screen (in a system file only root can read). 

sudo bash -c 'read -s -p "Service password: " p; echo; \
  nmcli connection modify uuid "PROFILE-UUID" vpn.secrets "password=$p"'

Add the service Username in the profile editor first.

nmcli connection edit uuid "PROFILE-UUID"
# inside the editor:
#   set vpn.user-name <service username>
#   save persistent
#   quit
Install it yourself · Step 3

Add shortcuts to turn it on and off

Add these two lines to the end of ~/.bashrc and you can use vpnon and vpnoff. 

alias vpnon='nmcli connection up uuid "PROFILE-UUID"'
alias vpnoff='nmcli --wait 25 connection down uuid "PROFILE-UUID"'

Open a new terminal, or run source ~/.bashrc, to use them.

05-3 · Pitfalls

What to watch out for when installing both

Turn both on the wrong way and you can lose your whole network connection. Both programs change internet routes and firewall rules, so they overwrite each other's settings. Avoid these three things.

Don't do this

  • Native NordVPN app (the nordvpn command) plus Tailscale: the app rewrites routing and firewall rules itself and collides with Tailscale. There's a real case of a system locking up badly enough to need a reinstall.
  • Tailscale exit nodes: they can't run alongside NordVPN. Don't pass an exit node option to tailscale up.
  • Nord Meshnet: it uses the same 100.64.0.0/10 address range as Tailscale, so addresses collide.

The one safe combination verified for this guide is Tailscale (device mesh only) plus a NetworkManager OpenVPN profile. It has no kill switch: if NordVPN drops, traffic goes straight back to your regular connection (fail-open). That's intentional, to keep Tailscale remote access working, but it doesn't suit privacy needs where the VPN must never drop.

05-4 · Together

Using Tailscale and NordVPN together

Why use both? They do different jobs: Tailscale reaches your own devices (a file server, say), and NordVPN routes the rest of the internet through a server in the country you choose. With both on, you can browse through a server in Japan while still reaching your Samba file server over Tailscale.

The trick is simple. Tailscale only manages its own device addresses, like 100.x.x.x, and NordVPN runs only as a NetworkManager profile that handles everything else. This was verified on the author's machine: with NordVPN on, Tailscale pings and the file server keep working, and turning NordVPN off returns you to your regular connection immediately.

Check it yourself

Confirm the split

With NordVPN on, run these:

curl https://api.ipify.org          # should print a NordVPN server IP
tailscale ping <other-device-name>  # Tailscale stays up
ip route get 100.76.206.87          # check table 52 via tailscale0

Turn the connection off (vpnoff) and you're back on your regular connection while Tailscale stays up.

Ask an AI

My computer runs Omarchy (Arch Linux). I want to use Tailscale and NordVPN together.
Set it up following these rules.
1. Tailscale is mesh-only (no exit node, --accept-routes=false)
2. NordVPN only as a NetworkManager OpenVPN profile, not the native app
3. Autoconnect off, and no kill switch (fail-open is intended)
4. Don't turn on Nord Meshnet (it overlaps Tailscale's 100.64.0.0/10 range)
5. Verify afterwards: with Nord on, curl https://api.ipify.org shows a Nord IP,

   Also check that turning Nord off returns to the regular connection.

05-5 · Bar icons

Add VPN toggle icons to the bar

Instead of typing commands every time, you can switch the VPNs from icons in the bar at the top of the screen. Omarchy's bar (Quickshell) supports user plugins, so this guide adds two icons. Each icon shows only while its VPN is on and stays hidden otherwise until you hover over it, the same way the caffeine icon next to the clock works. Click an icon to turn that VPN on or off.

Install it yourself

One script does it

The script checks what you have installed first. With only Tailscale it adds just the link icon; with only a NetworkManager VPN profile, just the shield; with both, both. If neither is installed, it tells you to install one first. 

cd omarchy-starter
./install-vpn-bar-toggles.sh

It only changes your user settings, without sudo. For the Tailscale icon to work without a password prompt, run this once: 

sudo tailscale set --operator=$USER

To remove the icons:

./install-vpn-bar-toggles.sh --uninstall

05-6 · More settings

Other VPNs and bypass routes

Other VPN providers

Import a work VPN or another provider's config

Check whether the file from your employer or provider is a WireGuard .conf or an OpenVPN .ovpn, then import it as below. Config files can contain private keys, so don't upload them to GitHub. 

chmod 600 /path/to/provider.conf
omarchy pkg add wireguard-tools
nmcli connection import type wireguard file /path/to/provider.conf

chmod 600 /path/to/provider.ovpn
omarchy pkg add networkmanager-openvpn
nmcli connection import type openvpn file /path/to/provider.ovpn
Check and disconnect

See the active connections

nmcli connection show --active

Use the same connection name to turn a VPN off.

nmcli connection down "connection name"
Optional — Extra bypass routes

Manage addresses that skip the VPN

Tailscale devices already go through Tailscale automatically. If you need other IPs or CIDRs to bypass the VPN, use the tool in this folder. The config file takes one CIDR per line. 

mkdir -p ~/.config/doc-newbie
cp vpn-bypass-routes.conf.example ~/.config/doc-newbie/vpn-bypass-routes.conf
# replace the TEST-NET placeholders in the example with the CIDRs to bypass
./manage-vpn-bypass-routes.sh validate    # check the config only

./manage-vpn-bypass-routes.sh list        # list them

06 · Optional — KakaoTalk and screenshots

KakaoTalk and screenshots.

Neither is essential to Omarchy, but Korean users need KakaoTalk, and laptops without a Print key miss a screenshot shortcut. This chapter installs the Windows version of KakaoTalk with Bottles or Wine, and adds Mac-style capture shortcuts plus a capture button in the bar.

06-1 · KakaoTalk

Pick one of two ways to install it

KakaoTalk has no Linux version, so you run the Windows program on Linux. There are two ways to do that.

  • i.
    Bottles (Flatpak) Recommended · tested

    The method verified for this guide. The installer also applies Korean fonts and the chat input fix.

  • ii.
    Wine (AUR package kakaotalk) Experimental · being verified

    Lighter, but still being verified.

If you install both, you get two separate KakaoTalk apps, each with its own login and chat data.

Route 1 · Recommended — Bottles

Run the script and follow the screen

Bottles runs Windows programs on Linux. The script installs Flatpak and Bottles, creates the bottle, and registers the app for you. When the Windows installer window opens partway through, just click "Next." 

cd omarchy-starter
./install-kakaotalk-bottles.sh

If the KakaoTalk installer isn't in your Downloads folder yet, the official download page opens. Download the Windows PC version, then run the script again. If Super + Shift + K is free, it becomes the KakaoTalk shortcut automatically (the script leaves it alone if it's already taken).

To remove it:

./install-kakaotalk-bottles.sh --uninstall

Route 2 · Experimental — Wine

A lighter install from the AUR

The AUR package kakaotalk runs KakaoTalk with Wine. It's lighter than Bottles but still being verified, so fall back to route 1 if it gives you trouble. 

omarchy pkg aur add kakaotalk

On the author's machine, the Wine system tray is hidden

The Windows version of KakaoTalk creates a separate tray window that floats in the top-right corner. To get rid of it, wine-tray-hide is set up to hide that window at all times. KakaoTalk keeps running in the background without it, and Super + Shift + K brings the main window back.

To show the Wine tray again, stop the hiding daemon, comment out the autostart line below in ~/.config/hypr/autostart.lua, then quit KakaoTalk completely and start it again. 

pkill -f '^bash .*/wine-tray-hide$'
micro ~/.config/hypr/autostart.lua

# put -- in front of this line:
-- o.launch_on_start("wine-tray-hide")

hyprctl reload

If you don't comment out that line, the daemon starts again at your next login.

06-2 · Screenshots

Take screenshots the Mac way

On laptops without a Print key, Mac-style shortcuts are handy. These match the Mac's Command + Shift + 4 (area) and Command + Shift + 3 (full screen). Captures are saved to ~/Pictures and copied to the clipboard. The script also unbinds Omarchy's defaults that use the same keys (moving a window to workspace 9 or 10), so only the capture fires. If you'd rather not learn shortcuts, click the camera button next to the clock in the bar. It always takes a full-screen capture and is always visible.

Install it yourself

Add the shortcuts and the bar button in one go

cd omarchy-starter
./install-screenshot-shortcuts.sh
  • Super + Shift + 9: capture an area
  • Super + Shift + 0: capture the full screen
  • Camera button in the bar: capture the full screen

To remove them:

./install-screenshot-shortcuts.sh --uninstall
